# 第2期 最小消息通信闭环 todo

## 使用说明

- 第2期默认依赖第1期已稳定运行。
- 本期按“AI 导师会话 -> 预约与通知 -> 私密聊天室”顺序执行。
- 每个子闭环先做后端，再做前端，再做联调验收。

## 阶段一：AI导师会话闭环

### 1. 数据模型

- [ ] 建立 `ai_chat_session` 表，包含学生 ID、会话标题、状态、最后活跃时间、摘要、风险标记。
- [ ] 建立 `ai_chat_message` 表，包含会话 ID、发送方类型、消息内容、风险等级、创建时间。
- [ ] 为高风险关键词命中结果预留字段，便于后续升级风险策略。

### 2. 会话接口

- [ ] 实现 `POST /api/student/ai-sessions` 创建 AI 会话接口。
- [ ] 实现 `GET /api/student/ai-sessions` 学生会话列表接口。
- [ ] 实现 `GET /api/student/ai-sessions/{sessionId}/messages` 学生查看历史消息接口。
- [ ] 实现 `POST /api/student/ai-sessions/{sessionId}/messages` 学生发送消息接口。
- [ ] 发送消息时自动写入学生消息和 AI 回复消息。
- [ ] AI 回复调用 Spring AI，失败时回退到模板回复。

### 3. 风险与约束

- [ ] 为 AI 提示词加入“温和、倾听、不下诊断”的角色约束。
- [ ] 建立高风险关键词检测逻辑。
- [ ] 命中高风险关键词时在消息和会话上记录风险标记。
- [ ] 高风险回复要输出更克制的兜底话术，并建议联系咨询师或可信支持者。

### 4. 权限边界

- [ ] 学生只能访问自己的 AI 会话和消息。
- [ ] 咨询师只能访问已绑定学生的 AI 会话轨迹。
- [ ] 实现 `GET /api/counselor/students/{studentUserId}/ai-sessions` 咨询师查看学生会话列表接口。
- [ ] 实现 `GET /api/counselor/students/{studentUserId}/ai-sessions/{sessionId}/messages` 咨询师查看学生会话消息接口。
- [ ] 管理员本期不开放学生 AI 会话明细接口。

### 5. 联调与验收

- [ ] 使用 `curl` 验证学生创建会话成功。
- [ ] 使用 `curl` 验证学生发送消息后可收到 AI 回复。
- [ ] 使用 `curl` 验证学生历史消息查询成功。
- [ ] 使用 `curl` 验证咨询师能查看已绑定学生的会话轨迹。
- [ ] 使用 `curl` 验证未绑定咨询师无法越权访问。

## 阶段二：匿名预约与通知闭环

### 1. 数据模型

- [ ] 建立 `consult_appointment_slot` 表，存储咨询师可预约时段。
- [ ] 建立 `consult_appointment` 表，存储学生匿名代号、问题简介、预约时段、状态、处理结果。
- [ ] 建立 `site_notification` 表，存储站内通知标题、内容、接收人、已读状态、创建时间。

### 2. 匿名预约

- [ ] 为学生生成匿名代号规则，例如“向日葵同学”“银杏同学”。
- [ ] 实现 `GET /api/student/appointments/slots` 查询可预约时段接口。
- [ ] 实现 `POST /api/student/appointments` 学生发起匿名预约接口。
- [ ] 预约时校验时段有效、未被占用、学生已登录。
- [ ] 预约成功后自动给对应咨询师生成待办通知。

### 3. 咨询师接单

- [ ] 实现 `GET /api/counselor/appointments` 咨询师预约列表接口。
- [ ] 实现 `POST /api/counselor/appointments/{appointmentId}/accept` 咨询师接单接口。
- [ ] 实现 `POST /api/counselor/appointments/{appointmentId}/reject` 咨询师拒绝接口。
- [ ] 接单或拒绝后自动给学生生成结果通知。
- [ ] 预约状态流转要明确限制，只允许合法状态变更。

### 4. 通知中心

- [ ] 实现 `GET /api/notifications` 当前用户通知列表接口。
- [ ] 实现 `POST /api/notifications/{notificationId}/read` 单条已读接口。
- [ ] 实现 `POST /api/notifications/read-all` 全部已读接口。
- [ ] 学生和咨询师都只能查看自己的通知。

### 5. 联调与验收

- [ ] 使用 `curl` 验证学生能查询时段并成功发起匿名预约。
- [ ] 使用 `curl` 验证咨询师能看到新的预约待办。
- [ ] 使用 `curl` 验证咨询师接单后学生能收到通知。
- [ ] 使用 `curl` 验证拒绝、取消、重复接单等非法流转会被拦截。

## 阶段三：私密聊天室闭环

### 1. 数据模型

- [ ] 建立 `consult_chat_session` 表，关联预约单、开放时间、关闭时间、状态。
- [ ] 建立 `consult_chat_message` 表，记录发送方、消息内容、消息时间、是否封存。
- [ ] 预留消息加密或脱敏存储字段。

### 2. WebSocket 基础

- [ ] 配置 WebSocket 入口与握手鉴权。
- [ ] 握手时校验当前用户是否属于该预约双方。
- [ ] 握手时校验是否处于预约有效时间段内。
- [ ] 超时或结束后自动关闭连接并禁止继续写入。

### 3. 聊天功能

- [ ] 实现学生进入聊天室能力。
- [ ] 实现咨询师进入聊天室能力。
- [ ] 实现文字消息收发。
- [ ] 实现历史消息查询接口。
- [ ] 结束后将会话状态改为已封存。
- [ ] 已封存会话只允许查询，不允许发送。

### 4. 安全与隐私

- [ ] 前端默认展示匿名代号，不展示学生真实姓名。
- [ ] 管理员仍无权直接查看聊天室明文消息。
- [ ] 高敏感消息至少做存储层脱敏或加密封装。
- [ ] 聊天消息写入审计时只记录动作，不记录明文内容。

### 5. 联调与验收

- [ ] 本地联调验证学生与咨询师可在预约时间内建立连接。
- [ ] 验证双方消息互通正常。
- [ ] 验证预约时间外无法接入聊天室。
- [ ] 验证会话结束后不能继续发送消息。
- [ ] 验证历史消息可查询，且封存后仍保持只读。
