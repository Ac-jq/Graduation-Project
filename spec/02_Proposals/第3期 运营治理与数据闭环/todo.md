# 第3期 运营治理与数据闭环 todo

## 使用说明

- 第3期依赖前两期的测评、会话、预约等业务数据已经稳定沉淀。
- 本期按“资源库 -> 统计分析 -> 管理员 AI 运维”顺序执行。
- 所有管理端能力都要保留审计日志。

## 阶段一：自助资源库闭环

### 1. 数据模型

- [ ] 建立 `resource_category` 表，存储资源分类。
- [ ] 建立 `resource_tag` 表，存储资源标签。
- [ ] 建立 `mental_resource` 表，存储资源标题、简介、类型、地址、封面、状态、分类。
- [ ] 建立 `resource_tag_relation` 表，存储资源与标签的多对多关系。
- [ ] 建立 `resource_favorite` 表，存储学生收藏关系。

### 2. 学生侧资源浏览

- [ ] 实现 `GET /api/resources` 资源列表接口。
- [ ] 支持分类筛选、标签筛选、关键字搜索。
- [ ] 实现 `GET /api/resources/{resourceId}` 资源详情接口。
- [ ] 详情接口返回资源标签、分类、内容地址、收藏状态。
- [ ] 对下架资源在学生侧隐藏。

### 3. 收藏夹

- [ ] 实现 `POST /api/student/favorites/{resourceId}` 收藏资源接口。
- [ ] 实现 `DELETE /api/student/favorites/{resourceId}` 取消收藏接口。
- [ ] 实现 `GET /api/student/favorites` 我的收藏列表接口。
- [ ] 防止重复收藏造成重复数据。

### 4. 管理端资源管理

- [ ] 实现 `POST /api/admin/resources` 新建资源接口。
- [ ] 实现 `PUT /api/admin/resources/{resourceId}` 编辑资源接口。
- [ ] 实现 `POST /api/admin/resources/{resourceId}/publish` 上架接口。
- [ ] 实现 `POST /api/admin/resources/{resourceId}/offline` 下架接口。
- [ ] 实现分类与标签维护接口。
- [ ] 所有资源管理动作写入审计日志。

### 5. 联调与验收

- [ ] 使用 `curl` 验证学生能按分类和标签查询资源。
- [ ] 使用 `curl` 验证学生收藏和取消收藏成功。
- [ ] 使用 `curl` 验证管理员可新建、编辑、上下架资源。
- [ ] 使用 `curl` 验证下架资源不会出现在学生列表中。

## 阶段二：数据统计与反馈闭环

### 1. 统计口径先固化

- [ ] 明确日活、测评完成人数、资源访问量、AI 会话次数、预约次数等统计口径。
- [ ] 明确前后测对比所用量表范围与时间范围。
- [ ] 明确学院、年级、性别等聚合维度。
- [ ] 在文档中写明每个指标的计算规则，避免前后端理解偏差。

### 2. 看板接口

- [ ] 实现 `GET /api/admin/statistics/overview` 运营总览接口。
- [ ] 实现 `GET /api/admin/statistics/assessments` 测评统计接口。
- [ ] 实现 `GET /api/admin/statistics/resources` 资源使用统计接口。
- [ ] 实现 `GET /api/admin/statistics/appointments` 预约与咨询统计接口。
- [ ] 接口结果只返回聚合数据，不返回学生身份明细。

### 3. 前后测对比

- [ ] 实现同类量表前后测对比分析逻辑。
- [ ] 输出平均分变化、等级分布变化、参与人数变化等指标。
- [ ] 对样本数过小的结果增加提示，避免误读。

### 4. 报表导出

- [ ] 实现按学院维度导出统计报表。
- [ ] 实现按年级维度导出统计报表。
- [ ] 实现按性别维度导出统计报表。
- [ ] 导出文件中不得出现姓名、学号等直接身份标识。

### 5. 联调与验收

- [ ] 使用 `curl` 验证总览统计接口返回聚合数据。
- [ ] 使用 `curl` 验证前后测对比接口可正常返回结果。
- [ ] 使用 `curl` 验证报表导出成功。
- [ ] 检查导出文件不包含学生姓名、学号等敏感信息。

## 阶段三：管理员AI运维闭环

### 1. 数据模型

- [ ] 建立 `admin_ai_task` 表，存储管理员原始指令、解析状态、确认状态、执行状态。
- [ ] 建立 `admin_ai_task_item` 表，存储待执行操作清单明细。
- [ ] 明细项包含目标对象、操作类型、字段名、旧值、新值、执行顺序。

### 2. 指令解析

- [ ] 实现 `POST /api/admin/ai-tasks/parse` 指令解析接口。
- [ ] 将自然语言指令解析成结构化执行计划。
- [ ] 第一批只支持账号启停、咨询师账号创建、资源上下架三个场景。
- [ ] 若意图不明确，返回需补充信息而不是盲目生成计划。

### 3. 待执行清单

- [ ] 实现 `GET /api/admin/ai-tasks/{taskId}` 查询任务详情接口。
- [ ] 实现待执行清单展示结构，包含受影响对象、字段变更、新旧值对比。
- [ ] 未经人工确认前，任何计划不得直接落库。

### 4. 人工确认执行

- [ ] 实现 `POST /api/admin/ai-tasks/{taskId}/confirm` 确认执行接口。
- [ ] 实现 `POST /api/admin/ai-tasks/{taskId}/cancel` 取消执行接口。
- [ ] 确认执行时再次校验目标对象是否仍处于可执行状态。
- [ ] 执行结果写回任务主表和明细表。
- [ ] 所有确认执行动作写入审计日志。

### 5. 联调与验收

- [ ] 使用 `curl` 验证管理员可提交自然语言指令并拿到执行计划。
- [ ] 使用 `curl` 验证计划中能看到对象范围与新旧值对比。
- [ ] 使用 `curl` 验证未确认前系统不会执行 CRUD。
- [ ] 使用 `curl` 验证确认后数据才真正落库。
- [ ] 使用 `curl` 验证取消后任务状态正确且不落库。
