# 第1期 基础功能建设（MVP）

## 1. 阶段目标

围绕 PRD 中的 P0 核心能力，先完成平台最小可运行骨架，打通“登录鉴权 -> 用户档案 -> 心理测评 -> AI 解读 -> 报告归档”的首个业务闭环，为后续在线咨询与消息链路提供稳定基础。

## 2. 阶段范围

### 2.1 本期纳入

- 用户管理模块中的账号登录、RBAC 鉴权、学生个人信息维护、密码修改与安全审计日志。
- 心理测评与 AI 解读模块中的量表库、答题流程、自动评分、AI 解读文本生成、测评报告归档。
- 首页首屏核心入口与三角色基础工作台骨架。
- 后端基础工程能力，包括统一 `Result` 返回、统一 `BusinessException`、全局异常处理、必要注释与基础配置。

### 2.2 本期不纳入

- AI 导师聊天、人工预约、排班通知、私密聊天室。
- 自助资源库、数据统计看板、管理员 AI 运维助手。
- PRD 中标注为 P2 的智能推荐联动能力。

## 3. 交付物

- 学生、咨询师、管理员三角色登录与基础菜单隔离。
- 学生个人资料维护页面与对应接口。
- 标准化量表管理、答题、评分、报告查询接口与页面。
- 测评报告 AI 解读能力，并将报告归档到学生心理档案。
- 面向咨询师的学生测评报告查看入口。
- 安全审计日志基础能力，至少覆盖登录、密码修改、测评提交。

## 4. 验收标准

- 三类角色均可通过 Web 端登录，且只能访问自身权限范围内的数据与菜单。
- 学生不可修改学号等核心学籍字段，只能修改允许开放的个人信息。
- 量表支持分页答题与进度保存，提交后可自动计算得分并生成报告。
- AI 解读结果可与量表得分一并保存，学生可查看自己的历史报告。
- 咨询师只能查看分配给自己的学生报告，管理员不能直接查看学生明文聊天记录。
- 所有 Controller 接口返回统一 `Result`，业务异常统一走 `BusinessException`。
- 每个已完成闭环必须启动服务并使用 `curl` 完成接口验收。

## 5. 依赖与约束

- 技术栈严格遵循 `AGENTS.md`：后端使用 Java 17、Spring Boot 3.2.12、MyBatis-Plus、MySQL、Sa-Token、Redis、Spring AI。
- 前端按 `AGENTS.md` 使用 Vue 3、Vite、Pinia、Element Plus、Tailwind CSS。
- 本期需要优先沉淀用户、角色、量表、题目、答卷、报告、审计日志等核心数据模型。

## 6. 风险与边界

- AI 解读文本必须定位为辅助解释，不输出诊断性结论。
- 测评算法与常模需要先固化为可配置规则，避免后续扩展量表时反复改表结构。
- 审计日志只记录关键行为，不记录不必要的敏感明文信息。
