# 第1期 基础功能建设（MVP）todo

## 使用说明

- 本清单按业务闭环顺序执行，不跨阶段并行。
- 每完成一个小闭环，都要启动项目并执行 `curl` 验证。
- 若某条完成后发现要补前置基础能力，先回填到当前阶段内解决，再继续向下推进。

## 阶段一：认证与身份闭环

### 1. 数据模型与初始化

- [ ] 建立 `sys_role` 表，包含角色编码、角色名称、描述、创建时间。
- [ ] 建立 `sys_user` 表，包含账号、加盐密码摘要、角色编码、真实姓名、显示名称、学号、工号、状态、时间字段。
- [ ] 建立 `sys_audit_log` 表，包含操作人、动作编码、动作名称、详情、IP、创建时间。
- [ ] 编写 `schema.sql`，保证数据库启动时可自动初始化上述表结构。
- [ ] 编写演示数据初始化逻辑，至少插入学生、咨询师、管理员三个角色与三个账号。
- [ ] 演示账号要写入清晰默认密码，方便本地联调和 `curl` 验证。

### 2. 认证与会话

- [ ] 封装密码加密工具，使用 Bouncy Castle 做带盐摘要。
- [ ] 接入 Sa-Token 登录态，封装获取当前登录用户 ID 的通用工具。
- [ ] 实现 `POST /api/auth/login` 登录接口。
- [ ] 实现 `POST /api/auth/logout` 登出接口。
- [ ] 实现 `GET /api/auth/current-user` 获取当前用户接口。
- [ ] 实现 `POST /api/auth/change-password` 修改密码接口。
- [ ] 修改密码时校验旧密码、新密码、确认密码一致性。
- [ ] 账号被禁用时禁止登录。

### 3. 角色与边界

- [ ] 建立 Sa-Token 角色提供器，保证学生、咨询师、管理员能按角色识别。
- [ ] 配置 `/api/**` 默认登录校验，放行 `system` 探活接口和登录接口。
- [ ] 为学生、咨询师、管理员接口加角色校验注解。
- [ ] 保证所有 Controller 返回统一 `Result`。
- [ ] 保证所有业务错误统一抛 `BusinessException`。

### 4. 审计日志

- [ ] 登录成功后记录审计日志。
- [ ] 主动登出后记录审计日志。
- [ ] 修改密码后记录审计日志。
- [ ] 审计日志中只记录必要业务信息，不写入敏感明文密码。

### 5. 启动与验收

- [ ] 启动项目，确认数据库表自动初始化成功。
- [ ] 使用 `curl` 验证学生登录成功。
- [ ] 使用 `curl` 验证咨询师登录成功。
- [ ] 使用 `curl` 验证管理员登录成功。
- [ ] 使用 `curl` 验证获取当前用户接口返回角色信息。
- [ ] 使用 `curl` 验证修改密码后可用新密码重新登录。
- [ ] 使用 `curl` 验证未登录访问受保护接口会返回统一未授权结果。

## 阶段二：学生档案与量表作答闭环

### 1. 学生档案模型

- [ ] 建立 `student_profile` 表，包含学院、年级、性别、联系电话、紧急联系人、紧急联系人电话、负责咨询师等字段。
- [ ] 建立 `counselor_student` 表，用于咨询师与学生授权绑定关系。
- [ ] 为演示学生初始化默认档案数据。
- [ ] 为演示咨询师与学生建立默认绑定关系。

### 2. 学生档案接口

- [ ] 实现 `GET /api/student/profile/me` 查询当前学生档案接口。
- [ ] 实现 `PUT /api/student/profile/me` 更新当前学生档案接口。
- [ ] 只允许学生访问自己的档案接口。
- [ ] 更新接口只开放学院、年级、性别、电话、紧急联系人等允许修改字段。
- [ ] 禁止通过任何接口修改学号、角色、账号状态等核心学籍与身份字段。

### 3. 量表基础模型

- [ ] 建立 `mental_scale` 表，包含编码、名称、说明、须知、题目数、分页大小、风险阈值、状态。
- [ ] 建立 `mental_scale_question` 表，包含量表 ID、题号、题干、是否必答。
- [ ] 建立 `mental_scale_option` 表，包含题目 ID、选项编码、选项文案、分值、排序号。
- [ ] 建立 `mental_scale_session` 表，包含量表 ID、学生 ID、状态、已答题数、总分、提交时间。
- [ ] 建立 `mental_scale_answer` 表，包含会话 ID、题目 ID、选项 ID、得分。
- [ ] 初始化至少一份可跑通的演示量表，建议直接放 `PHQ-9`。

### 4. 量表查询与草稿会话

- [ ] 实现 `GET /api/scales` 量表列表接口。
- [ ] 实现 `GET /api/scales/{scaleId}` 量表详情接口。
- [ ] 实现 `POST /api/scales/{scaleId}/sessions/draft` 创建或获取草稿会话接口。
- [ ] 草稿会话要支持同一学生同一量表复用未提交会话，避免重复造多份草稿。

### 5. 分页作答与保存

- [ ] 实现 `GET /api/scales/sessions/{sessionId}/questions` 分页题目查询接口。
- [ ] 分页查询要返回题目、选项、当前已选答案、已答数量、总题数。
- [ ] 实现 `PUT /api/scales/sessions/{sessionId}/answers` 批量保存答案接口。
- [ ] 保存答案时校验题目属于当前量表。
- [ ] 保存答案时校验选项属于当前题目。
- [ ] 保存后自动回写会话的 `answeredCount`。
- [ ] 已提交的会话禁止继续修改答案。

### 6. 提交评分

- [ ] 实现 `POST /api/scales/sessions/{sessionId}/submit` 提交量表接口。
- [ ] 提交前校验题目全部完成作答。
- [ ] 提交时自动累计总分。
- [ ] 提交时根据量表阈值计算风险等级。
- [ ] 提交后将会话状态改为 `SUBMITTED`。
- [ ] 提交动作写入审计日志。

### 7. 启动与验收

- [ ] 启动项目，确认量表、题目、选项、会话、答案表正常初始化。
- [ ] 使用 `curl` 验证学生可查询自己的档案。
- [ ] 使用 `curl` 验证学生更新档案成功且学号未被修改。
- [ ] 使用 `curl` 验证学生能获取量表列表与量表详情。
- [ ] 使用 `curl` 验证草稿会话创建成功。
- [ ] 使用 `curl` 验证分页题目查询返回已选答案与进度信息。
- [ ] 使用 `curl` 验证三页答案分批保存后 `answeredCount` 正确累计。
- [ ] 使用 `curl` 验证提交后返回总分与风险等级。

## 阶段三：AI解读与报告归档闭环

### 1. 报告模型

- [ ] 建立 `mental_scale_report` 表，包含会话 ID、量表 ID、学生 ID、风险等级、总分、评分总结、AI 解读、创建时间。
- [ ] 保证同一提交会话只生成一份报告。
- [ ] 报告表和作答会话通过外键或逻辑关联绑定。

### 2. AI解读服务

- [ ] 封装 `AiInterpretationService`，提供统一的 AI 解读入口。
- [ ] 先接入 Spring AI 的 `ChatModel` 调用能力。
- [ ] 给 AI 设定“温和、客观、非诊断性”的提示词约束。
- [ ] 当本地未配置可用模型或模型调用失败时，自动回退到模板化解读文案。
- [ ] 兜底文案仍要按低、中、高三个等级输出不同文本。

### 3. 报告生成与归档

- [ ] 在量表提交成功后自动生成报告记录。
- [ ] 报告中保存总分、等级、评分总结、AI 解读文本。
- [ ] 提交接口直接返回 `reportId`，便于前端跳转报告详情。
- [ ] 保证重复提交同一会话时不会生成多份报告。

### 4. 学生报告查询

- [ ] 实现 `GET /api/student/reports` 当前学生历史报告列表接口。
- [ ] 实现 `GET /api/student/reports/{reportId}` 当前学生报告详情接口。
- [ ] 学生只能查看自己的报告。
- [ ] 列表接口返回量表名称、总分、等级、摘要、创建时间。
- [ ] 详情接口返回完整 AI 解读文本。

### 5. 咨询师查看授权学生报告

- [ ] 实现 `GET /api/counselor/students/{studentUserId}/reports` 咨询师查看学生报告列表接口。
- [ ] 实现 `GET /api/counselor/students/{studentUserId}/reports/{reportId}` 咨询师查看学生报告详情接口。
- [ ] 查询前校验咨询师与学生存在绑定关系。
- [ ] 未绑定的咨询师访问时返回统一业务异常。
- [ ] 管理员本阶段不开放学生报告明细接口。

### 6. 启动与验收

- [ ] 启动项目，确认提交量表后自动生成报告记录。
- [ ] 使用 `curl` 验证学生提交量表后返回 `reportId`。
- [ ] 使用 `curl` 验证学生历史报告列表查询成功。
- [ ] 使用 `curl` 验证学生报告详情能返回 AI 解读文本。
- [ ] 使用 `curl` 验证咨询师可以查看已绑定学生的报告。
- [ ] 使用 `curl` 验证未绑定咨询师无法越权查看其他学生报告。
- [ ] 使用 `curl` 验证管理员没有直接查看学生报告明细的接口入口。
