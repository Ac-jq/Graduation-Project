# 高校心理自助服务平台 前端设计文档

## 1. 文档边界

本文档仅定义前端系统逻辑，不涉及以下内容：
- 页面视觉风格
- 排版方案
- 组件库嵌套细节
- Tailwind / Element Plus 的具体类名与样式写法

前端职责限定为：
- Vue 3 + Vite 工程化基建
- Vue Router 路由控制
- Pinia 全局状态管理
- Axios 请求封装
- 权限校验、数据缓存、表单提交、WebSocket 会话管理

### 2.3 路由权限校验逻辑

#### 公共路由

| 路由 | 权限 | 校验规则 |
| --- | --- | --- |
| `/login` | 公开 | 已登录用户根据 `roleCode` 重定向到各自主工作区 |
| `/forbidden` | 公开 | 仅展示无权限状态 |
| `/not-found` | 公开 | 404 路由 |

#### 学生路由

| 路由 | 角色 | 进入前校验 |
| --- | --- | --- |
| `/student/**` | `STUDENT` | 未登录跳 `/login`；非 `STUDENT` 跳 `/forbidden` |
| `/student/assessment-sessions/:sessionId` | `STUDENT` | 附加校验 `sessionId` 必须可被当前学生访问，否则跳报告列表或错误页 |
| `/student/reports/:reportId` | `STUDENT` | 附加校验 `reportId` 属于本人 |
| `/student/ai-sessions/:sessionId` | `STUDENT` | 附加校验 `sessionId` 属于本人 |
| `/student/chat/appointments/:appointmentId` | `STUDENT` | 附加校验预约主体身份与聊天时间窗口 |

#### 咨询师路由

| 路由 | 角色 | 进入前校验 |
| --- | --- | --- |
| `/counselor/**` | `COUNSELOR` | 未登录跳 `/login`；非 `COUNSELOR` 跳 `/forbidden` |
| `/counselor/students/:studentUserId/**` | `COUNSELOR` | 附加校验学生是否在绑定列表中 |
| `/counselor/chat/appointments/:appointmentId` | `COUNSELOR` | 附加校验预约是否分配给当前咨询师 |

#### 管理员路由

| 路由 | 角色 | 进入前校验 |
| --- | --- | --- |
| `/admin/**` | `ADMIN` | 未登录跳 `/login`；非 `ADMIN` 跳 `/forbidden` |
| `/admin/scales/:scaleId` | `ADMIN` | 附加校验量表存在性 |
| `/admin/resources/:resourceId` | `ADMIN` | 附加校验资源存在性 |

## 3. 全局状态管理 (Pinia Store)

### 3.1 Store 划分原则

- `authStore`：只处理登录态、token、角色与会话恢复
- `userStore`：只处理当前用户资料与跨页面基础身份信息
- 业务模块独立 store，不在页面内重复维护缓存
- 列表页与详情页共享查询结果时，优先通过 store 做标准化缓存
- 所有 store 的异步行为统一调用 `api/*` 请求层，不直接在组件里写裸请求

### 3.2 authStore

#### State

```ts
type AuthState = {
  token: string | null
  roleCode: 'STUDENT' | 'COUNSELOR' | 'ADMIN' | null
  userId: number | null
  account: string | null
  displayName: string | null
  roles: string[]
  loginPending: boolean
  bootstrapped: boolean
}
```

#### Actions

- `login(payload)`：调用 `POST /api/auth/login`
- `fetchCurrentUser()`：调用 `GET /api/auth/current-user`
- `logout()`：调用 `POST /api/auth/logout`
- `changePassword(payload)`：调用 `POST /api/auth/change-password`
- `restoreSession()`：从本地存储恢复 token 并回填用户信息
- `clearSession()`：清空 token、角色、缓存
- `resolveHomeRoute()`：按角色返回默认首页

建议目录：

```text
src/api/
├─ http.ts             # axios 实例、拦截器、错误归一化
├─ auth.ts
├─ assessment.ts
├─ ai-chat.ts
├─ appointment.ts
├─ notification.ts

   ├─ common.ts
   ├─ auth.ts
   ├─ assessment.ts

   ├─ resource.ts
   └─ admin.ts
```

统一响应泛型：

```ts
type ApiResult<T> = {
  code: number
  message: string
  data: T
  timestamp: string
}
```

统一拦截规则：
- `401`：清空登录态并跳 `/login`
- `403`：跳 `/forbidden`
- `600`：以业务错误形式交给页面逻辑处理
- `500`：统一错误通道，不在组件内散落重复判断

完成标准：
- 所有核心接口都能在 store action 中被单独调用
- store 间职责清晰，不出现页面直接维护全局共享数据
- WebSocket 连接逻辑归口到 store 或 composable，而不是页面散落实现

### P2 - 各页面骨架

目标：
- 仅完成 `<script setup>` 级别业务逻辑
- 页面完成路由参数解析、store 绑定、数据预取、提交动作、异常处理
- 本阶段不展开视觉细节与模板布局设计

页面范围：
- 学生端业务骨架
- 咨询师端业务骨架
- 管理员端业务骨架

建议目录：

```text
src/views/
├─ public/
├─ student/
├─ counselor/
└─ admin/
```

每个页面骨架应至少包含：
- 路由参数读取
- 页面进入时的 `onMounted` / `watch` 数据加载
- 提交动作与 loading 状态
- 对 `401/403/600/500` 的分支处理
- 对 store action 的调用关系

## 6. 推荐实现约束

### 6.1 页面级 composable

适合抽离的逻辑：
- `useAuthRedirect()`
- `usePaginationQuery()`
- `useAssessmentSession()`
- `useConsultChatSocket()`
- `useNotificationPolling()`
- `useRoleMenu()`

### 6.2 本地缓存策略

- `token`、`roleCode`、`userId`：持久化
- `currentUser`：可持久化，但应用启动后应再次校验
- 列表数据：默认内存缓存，不强持久化
- 报告详情、量表详情：可做短期内存缓存
- 聊天消息：页面离开即释放，避免长驻内存

### 6.3 前端错误恢复原则

- 登录失效：强制回登录页
- 业务错误：页面内提示并保留上下文
- 路由参数非法：回到上一层列表页
- WebSocket 断连：允许重连，不阻塞历史消息读取

## 7. 文档结论

前端系统应采用“路由驱动 + Store 中心化 + API 模块化”的结构：
- Router 负责身份边界和页面切换
- Pinia 负责缓存、数据流和业务动作
- API 层负责协议收口
- 页面骨架只组合路由参数、store action 与错误处理

该结构可以保证：
- 逻辑与视图彻底分离
- 前端可并行开发
- 后续视觉层可替换而不影响业务逻辑层
