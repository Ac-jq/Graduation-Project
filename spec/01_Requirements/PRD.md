# 《高校心理自助服务平台》产品需求文档 (PRD)

---

## 1. 项目背景与目标

**1.1 项目背景**
近年来，随着学业竞争、就业压力以及人际交往环境的复杂化，在校大学生的心理压力日益增加，心理健康问题呈现多发态势。传统的心理干预主要依赖线下面对面咨询，但这种模式存在诸多局限性：一方面，学校心理师资力量有限，难以覆盖所有具有潜在需求的学生，导致干预效率较低；另一方面，学生普遍存在“病耻感”或对个人隐私泄露的顾虑，往往抗拒主动走进心理咨询室。

**1.2 产品目标**
为打破传统心理咨询的壁垒，本平台旨在打造一个纯Web端的“高校心理自助服务平台”。通过引入全天候在线干预机制与前沿的AI拟人化技术，为学生提供便捷、安全、隐蔽的心理支持。
* **对学生：** 降低求助门槛，提供24小时的“AI导师”陪伴与科学的自助调节手段，化被动干预为主动预防。
* **对咨询师：** 提供高效的工作台，通过AI预检和数据沉淀，精准掌握学生心理动态，提升干预效率。
* **对校方：** 建立完善的心理健康数字档案与宏观分析报表，提升学校心理健康教育与危机干预的整体水平。

## 2. 角色权限矩阵

本系统严格遵循纯Web端架构，所有交互均通过浏览器完成。系统将用户划分为三大核心角色，实施严格的数据隔离与权限管控。

| 角色名称 | 使用终端 | 核心目标 | 权限边界 |
| :--- | :--- | :--- | :--- |
| **学生** | Web前端 (面向全校学生) | 随时随地获取心理支持、自我排解情绪、安全地寻求专业帮助。 | 仅可查看和修改本人资料；可使用测评、AI导师、资源库；可发起咨询预约及参与匿名聊天室。**绝对禁止**查看他人任何数据。 |
| **心理咨询师** | Web工作台 (面向校内专业老师) | 处理学生咨询预约、在线辅导、监控高危学生心理动态。 | 可管理分配给自己的咨询预约；可进入专属在线聊天室；**核心权限**：可查阅向其授权或分配的学生的AI导师历史对话记录与心理测评报告。 |
| **管理员** | Web管理后台 (面向校心理中心主任/IT运维) | 宏观把控全校心理健康状况，维护系统基础数据与平台运转。 | 拥有最高系统配置权（角色分配、量表管理、资源库上下架）；可通过AI辅助助手使用自然语言进行系统运维管理；可查看全校脱敏后的宏观统计报表与审计日志；**无权**直接查看特定学生的明文聊天记录（需特殊授权脱敏流程）。 |

## 3. 模块优先级划分

根据核心业务路径与用户价值，系统功能模块优先级划分如下：

| 模块名称 | 优先级 | 核心说明 |
| :--- | :--- | :--- |
| **用户管理模块** | P0 (核心) | 系统的基石，支撑角色鉴权、安全准入与基础档案建立。 |
| **心理测评与AI解读模块** | P0 (核心) | 认知自我心理状态的第一步，AI解读增强互动性与可读性。 |
| **在线咨询与AI导师模块** | P0 (核心) | 核心干预手段，AI兜底全天候陪伴，人工咨询师解决深层问题。 |
| **管理员AI辅助运维模块** | P1 (重要) | 创新管理工具，通过自然语言提升后台日常运维效率。 |
| **自助资源模块** | P1 (重要) | 常态化的心理健康教育与自我调节工具库。 |
| **数据统计与反馈模块** | P1 (重要) | 形成管理闭环，为学校宏观决策和效果评估提供数据支撑。 |
| *系统日志与安全审计* | P2 (非核心) | 记录系统行为日志，保障平台数据安全与合规溯源（隐性模块）。 |

## 4. 详细功能点拆分

### 4.1 用户管理模块 (P0)
* **功能说明：** 负责全平台用户的生命周期管理、身份鉴权及个人信息维护。
* **详细业务点：**
  * **角色与权限控制：** 采用RBAC（基于角色的访问控制）逻辑，按学生、咨询师、管理员分配不同视图和操作菜单。
  * **个人信息维护：** 允许学生更新基础资料（头像、联系方式、紧急联系人等）。
  * **安全审计日志：** 系统在后台自动记录所有用户的关键操作行为（如登录、提交测评、发起预约、修改密码等），形成操作日志台账，供管理员进行问题追踪与安全审计。
* **业务规则：**
  * 学生的学号/初始学籍信息由平台统一导入，不可自行篡改核心学籍字段。
  * 密码修改需进行双重确认。

### 4.2 心理测评与AI解读模块 (P0)
* **功能说明：** 提供标准化的心理量表测试，并通过AI技术将枯燥的分数转化为具有温度的拟人化解读报告。
* **详细业务点：**
  * **标准化量表库：** 提供如SCL-90（症状自评量表）、PHQ-9（抑郁症筛查量表）等结构化问卷。支持分页答题、进度保存。
  * **自动评分与档案生成：** 用户提交后，系统根据量表标准算法瞬间生成原始分数与常模对比。
  * **【AI创新】深度拟人化解读：** 系统将得分结果输入AI引擎，生成通俗易懂、具有共情色彩的专属评估文本（例如：“你最近似乎承受了不小的学业压力，睡眠状态亮起了黄灯……”），消除传统医学报告的冰冷感。
  * **智能推荐联动（P2，二期延后实现）：** 报告末尾，系统基于分数阈值及AI分析结果，自动向该学生推荐匹配的自助文章、冥想音频，或直接弹出“建议预约咨询师”的快速通道。
* **前/后置条件：** 前置要求用户处于登录状态；后置条件为生成报告并归档至该学生的个人心理档案中。

### 4.3 在线咨询与AI导师模块 (P0)
* **功能说明：** 搭建学生与平台互动的核心桥梁，结合“机器秒级响应”与“人工深度干预”。
* **详细业务点：**
  * **【AI创新】全天候AI导师：** 提供一个类似微信聊天窗口的对话界面。学生可随时向“AI导师”倾诉烦恼。AI导师需设定为“温和、倾听、不乱下诊断”的辅导员人设，进行情绪安抚与疏导。
  * **咨询师监控与介入：** **（核心规则）** 学生与AI的完整聊天记录对指定的心理咨询师开放查阅。咨询师可通过工作台查看其负责学生的AI对话轨迹，以便在学生真正预约人工咨询时，提前掌握其真实的心理底色和危机预警信号。
  * **匿名人工预约：** 学生可选择以系统分配的匿名代号（如“向日葵同学”）发起人工咨询请求，填写问题简述并选择可预约的时段。
  * **排班与通知系统：** 请求提交后，系统自动通知对应的心理咨询师（站内信/待办事项）。咨询师确认接单后，学生端收到预约成功反馈。
  * **私密咨询聊天室：** 在预约时间段内，系统开放一对一专属Web聊天室，支持文字交互，结束后即刻封存对话记录，保障隐私。

### 4.4 自助资源模块 (P1)
* **功能说明：** 建立学校专属的心理健康数字图书馆，供学生自助学习与调节。
* **详细业务点：**
  * **多媒体内容矩阵：** 支持图文（心理科普文章）、视频（放松训练、瑜伽操）、音频（正念冥想、白噪音）的在线浏览与播放。
  * **主题标签分类：** 资源按业务场景分类，如：情绪调节、压力管理、人际关系、恋爱指导、职业规划等，支持标签多选检索。
  * **个人收藏夹：** 学生在浏览过程中可点击“心形”图标进行收藏，统一在“我的收藏”列表中管理，方便睡前或焦虑时快速调用。
* **业务规则：** 资源的上传、分类标签的定义、以及上下架管理均由管理员在后台执行。

### 4.5 数据统计与反馈模块 (P1)
* **功能说明：** 将平台产生的数据沉淀为可视化图表，为管理层提供决策依据。
* **详细业务点：**
  * **参与度看板：** 面向管理员提供全校维度的宏观数据，包括日活跃人数、测评完成总人次、各分类自助资源的点击/播放排行、AI导师互动频次等。
  * **干预效果评估（前后测对比）：** 系统支持对参加过多次同类型测评（如学期初测一次，学期末测一次）的学生群体进行数据比对，生成心理状态变化曲线，评估整体心理健康工作成效。
  * **定制化报表导出：** 支持按照学院、年级、性别等维度生成统计报表，供学校汇报与辅助下一学年心理工作计划制定。
* **业务规则：** 统计报表中的数据必须是聚合级别或经过高度脱敏的，严禁在宏观图表中暴露特定个体的姓名与学号等直接身份特征。

### 4.6 管理员AI辅助运维模块 (P1)
* **功能说明：** 为管理员提供极具技术亮点的“AI自然语言管理助手（Agent CRUD）”，简化后台繁琐的表单操作，提升运维效率。
* **详细业务点：**
  * **自然语言指令输入：** 管理员可在专属的交互窗口中，直接输入自然语言指令。例如：“帮我禁用三个月未登录的学生账号”、“新建一个心理咨询师账号，名字叫张三，工号是T001”、“把名为《考前焦虑缓解》的文章下架”。
  * **意图解析与操作映射：** 底层Agent接收文本后，自动解析管理员意图，并将其转化为系统级的具体数据增删改查（CRUD）操作指令。
* **核心业务规则（操作拦截与二次确认）：** 为保障系统绝对安全，AI禁止直接执行任何数据变更操作。Agent解析出执行计划后，必须在前端清晰呈现**“待执行的操作清单”**（包含将要受影响的数据行、具体更改的字段名及新旧值对比）。只有当管理员人工审查无误，并明确点击**“确认执行”**按钮后，数据变更才能真正落库生效；若解析有误，管理员可一键取消或重新输入指令。

## 5. 非功能性需求

* **5.1 界面与交互体验 (UX/UI)**
  * **视觉风格：** 整体UI必须采用温暖、宁静、低饱和度的色彩（如浅蓝、原木色、治愈绿），避免使用警示红等可能引起焦虑的颜色。
  * **操作便捷性：** 核心功能（测评、找AI倾诉、预约咨询）必须在首页第一屏露出，保证用户在3次点击内即可到达核心业务节点。界面布局需适应不同尺寸的主流PC浏览器。
* **5.2 信息安全与权限管控**
  * **数据隔离：** 严格执行横向与纵向权限隔离。咨询师仅能查看分配给自己的学生档案；管理员仅能看宏观数据与系统日志。
  * **AI数据合规：** 学生与AI导师的对话记录视同医疗级隐私档案，在数据库层面需采取必要的加密存储策略（业务侧感知为高度受控访问）。
* **5.3 隐私保护机制**
  * **强制匿名机制：** 在前端“在线咨询聊天室”以及“评价环节”中，系统需强制抹除真实姓名，以系统生成的随机代号展示，最大程度降低学生的“病耻感”与社交顾虑。
  * **防窥探设计：** Web端需具备超时自动登出机制（如30分钟无操作自动退出登录），防止学生在公共机房或宿舍离开时隐私泄露。
